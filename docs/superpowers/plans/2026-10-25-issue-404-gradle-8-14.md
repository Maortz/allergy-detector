## Why more than the issue text says (scope note)

The issue only names Gradle, but research in the Flutter 3.47.7 SDK (`/home/maortz/development/flutter/packages/flutter_tools/gradle/src/main/kotlin/DependencyVersionChecker.kt:94-109`) shows three hard-error floors:

| Dependency | Flutter 3.47.7 error floor | Repo today | Target |
|---|---|---|---|
| Gradle | 8.14.0 (`errorGradleVersion`) | 8.11.1 | **8.14.3** |
| AGP | 8.11.1 (`errorAGPVersion`) | 8.9.1 | **8.11.1** |
| KGP | 2.2.20 (`errorKGPVersion`) | 2.1.0 | **2.2.20** |

The Gradle check throws first, which masks the AGP and KGP errors; fixing only the wrapper would trade one build failure for the next. Bumping all three is still effort:S (three version strings + one DSL block). Compatibility: AGP 8.11.x requires Gradle ≥ 8.13 (8.14.3 OK); KGP 2.2.20 supports Gradle up to 8.14 and AGP up to 8.11 (OK); all three run on JDK 17 (Flutter's Java floor is 17, `errorJavaVersion`). Flutter 3.41.7 in CI accepts these (they are newer than its floors and below its known-max). Deliberately NOT moving to Gradle 9 / AGP 9 (Flutter's new template default): that drags in the `android.newDsl`/`android.builtInKotlin` migration and is not S-sized.

KGP 2.2 raised the deprecation of `android { kotlinOptions { … } }` to ERROR, so `app/android/app/build.gradle.kts` must switch to the top-level `kotlin { compilerOptions { … } }` block — exactly the form Flutter's own template uses (`/home/maortz/development/flutter/packages/flutter_tools/templates/app/android-kotlin.tmpl/app/build.gradle.kts.tmpl:41-45`).
